# YouTube → 歌詞頁／影片教學頁 → 等老師校對

兩條**分支**，先判斷是哪一條（使用者沒說就問）：

- **歌曲**：MV、歌曲 → `data/songs/<id>.json`，頁面 `/#/song/<id>`
- **影片**：廣告、短片、對話 → `data/videos/<id>.json`，頁面 `/#/video/<id>`

資料形狀以 `src/song/types.ts`、`src/video/types.ts` 為準；寫之前先讀，欄位說明都在註解裡。
範例：歌曲看 `data/songs/lunar-is-here.json`，影片看 `data/videos/deleaf-thanaka.json`。

## 共同規則

- **id**：英文小寫加連字號（`than-fai-kao`、`deleaf-thanaka`），先跟使用者確認。
- **`createdAt`**：新增時填當天 `YYYY-MM-DD`，放在 `id` 下一行（`song-build.py` 會自動填）。列表靠它排序，舊的在前；沒填的會排到最後。
- **音標**依 thai2english.com 的寫法（ป＝bp、ต＝dt，聲調符號、詞內連字號照網站輸出）。網站查不到的字，參考同網站相近拼法補上，並寫進 `note`。
- **泰文原文以字幕為準**。字幕本身寫錯或少了詞時，原文照字幕不改，在 `note` 記下哪裡和實際唱的／說的不同。
- 中文翻譯用台灣用語、口語自然；品牌名、人名的 `zh` 標「（品牌名）」「（人名）」。
- 「內容尚未製作」的空殼檔（`lines: []`）就是要補的對象：沿用它的 `id`、`createdAt`、`youtubeId`，其餘照下面分支填。

## 歌曲分支

1. **產生草稿**（專案根目錄）：
   ```bash
   python3 scripts/song-build.py <videoId> --id=<id>
   ```
   - 只用 YouTube **官方手動**泰文字幕。沒有手動字幕腳本會停下來：如實告訴使用者，不改用自動字幕。
   - 已有同名檔案會停下來。檔案是內容待製作的空殼時，跟使用者確認後加 `--force`，再把原本的 `createdAt` 改回去。
   - 缺套件：`pip3 install --user -r scripts/requirements.txt`（先問使用者）。
2. **填每一句**：每個字的 `rom`、`zh`，以及整句 `zh`。
   - `words` 的 `th` 接起來必須**完全等於** `th`（含空格，空格跟在前一個字後面）。斷詞只能切開或合併相鄰片段，不能改字。
   - 英文歌詞的 `rom` 留空。
   - 重複的副歌照樣填；要不要隱藏（`hidden`）讓老師決定。
3. **補充區塊**：
   - `notes`：約 6 個 `word` 加 3 個 `pattern`，挑歌裡學生最需要講的口語、方言、流行語與句型。每個都附 `explain` 和一個 `example`（th／rom／zh）。
   - `quiz`：3 題。`q` 寫泰文，`qZh` 是它的中文翻譯，`answer` 是正確選項的索引。
   - `images`：只有使用者提供圖片時才加，檔案放 `public/extras/songs/<id>/`。
4. **完成標準**：每一句的 `zh` 都有內容，每個泰文字都有 `rom` 和 `zh`，`notes` 和 `quiz` 都齊。全部填完才拿掉 `draft: true`；`draft` 還在的話學生列表看不到這首歌。

## 影片分支

沒有產生腳本，JSON 要自己寫。

**本機影片**（例：泰劇片段 mp4，常由 drama-clip-subtitle 加好泰文字幕）：檔案放 `public/extras/videos/<資料夾>/`，JSON 的 `youtubeId` 留空字串、`videoSrc` 填 `extras/videos/<資料夾>/<檔名>.mp4`，頁面就用 `<video>` 播放，校時、投影片照常能用。原文照旁邊的 `.th.srt`，再對照畫面的中文字幕；`duration` 用 `ffprobe` 看影像長度（範例：`data/videos/zhen-ling.json`）。

1. **抓字幕**：用 `youtube_transcript_api` 抓泰文字幕，快取到 `data/dictation/subtitles/<videoId>.json`。
   - 優先用手動字幕。只有自動字幕時，對照影片畫面上的文字校對；拿不準的句子設 `guess: true`，並在 `note` 說明字幕怎麼來的。老師登入時，這些句子會顯示「字幕不確定，請老師確認」，老師確認後自己改回 `false`；回報時也逐句列出來。
   - 字幕和畫面都看不出來的，問使用者，不要自己猜一句填進去當定稿。
   - 截畫面：Chrome 開影片頁，用 JS 設 `video.currentTime`、play 0.5 秒再 pause，再 zoom 截圖；清單類影片（Vogue「10 Things」）的品項字卡每張只停約 1 秒，要 0.5 秒一格掃。
   - 畫面字幕或字卡和旁白實際說的不一樣時，原文照旁白說的寫（7-Eleven 片尾：字卡「…เมื่อครูเปลี่ยน」，老師改成旁白的「ถ้าอยากให้…ครูต้องเปลี่ยนก่อน」），在 `note` 記下字卡寫法。
   - 老師說字幕檢查過了：拿掉 `note` 裡說明自動字幕怎麼校對的那段，也拿掉所有 `guess`。
2. **切句寫 `lines`**：每句只有 `start`，結束時間＝下一句的 `start`。`duration` 填影片秒數。
   - `words`：每個字的 `th`、`rom`、`zh`。這個字屬於某個句型時，加 `p: "<句型 id>"`。
   - `patterns`：列出這句用到的句型 id。
   - 口語填充詞（อ่า、เอ่อ、นั่นน่ะ）不寫進原文；同一個詞口誤重複唸兩次只寫一次；句尾單獨的 โอเค 歸到下一句開頭。
   - 固定組合當一個字斷，不要拆開：จริงๆ แล้ว（實際上）、ผลการสอบ（考試結果）。
   - 中文用台灣用語（ผ้าห่ม＝被子，不寫毯子）；中文整句照劇裡的口氣（ไม่ต้องมาอ้ำๆ อึ้งๆ＝少在那邊給我支支吾吾的）。
3. **補充區塊**：
   - `vocab`：只挑真正需要講解的字（約 10 個），不是台詞裡的每個字。每個附 `explain` 和 `example`；一個字要舉好幾種用法時改用 `examples` 陣列（例：เที่ยว 的一班、去程／回程、幾趟、航班）。
     - 不用講解（老師在 BusOnlineTicket 拿掉的）：語氣詞與口語問句尾（อ้าว、หรอ、วะ、เลย）、太基本的名詞（ตั๋ว）。
     - 也不用講解（《鎮靈》老師拿掉的）：句尾禮貌詞（ครับผม）；已經在句型或文化補充講到的字（ครั้งต่อไป、ตกใจหมด 有句型，ผู้หมวด、จ่า 在官階金字塔裡），不要重複一則單字。
     - 要講解：App／網購介面常見字（คลิก、พร้อม、ต้นทาง、ปลายทาง），成對的字各自一則，不要塞在另一則的說明裡。
     - 解釋只講這支影片用到的意思，不要順帶其他義項（例：講 เที่ยว「班次」時不提「去玩」，例句也避開 ไปเที่ยว）；可以補同類的實用詞（ใจดำ 補 หน้าเลือด）。
     - 不寫「製造笑點」這類對劇情效果的評論。
     - 例句要像真實對話；問答可以寫在同一個例句裡（ไปงานเลี้ยงกันยังไง เจอกันที่ต้นทางไหม），不要拆成兩個例句。
     - 解釋越短越好（Vogue 兩支老師刪掉的）：不寫「字面是…」、量詞說明、「影片裡某某說…」、「…常用」這類補述、其他說法（泰國人也常說 บีนี่）；字面一看就懂的（ถุงมือ、大衣外套）`explain` 留空字串。可以補同組字的實用詞（เสื้อกันหนาว 補 เสื้อกันฝน、หมวกกันแดด；หมวกไหมพรม 補 เสื้อไหมพรม）。
     - 外來語、品項名稱解釋一句就好：「英文 mask 的外來語，正式說法是 หน้ากากอนามัย。」
     - 保養品例句的動詞用 ใช้，不用 ทา。
   - `patterns`：3–4 個句型，id 用 `p1`、`p2`…。`th` 寫成「ทำให้ + 受詞 + 狀態」這種公式，各附 2 個例句。陣列順序照第一次出現的句子排。
     - 不用列：แล้ว（已經…了）、ไม่ต้อง（不用）這類初級就會的。
     - 要列：功能詞的特殊用法（感受詞 + กับ「對於」、量詞 + เดียว、เพียง…ก็…）。例句要用講的那個意思造，不要混別的用法。
     - 公式和例句用台詞裡的那個說法（台詞是 ถ้าเกิด…ต้อง，公式和例句都用 ถ้าเกิด），句型掛在用那個說法的那句；`p` 改了句子後，id 照第一次出現的順序重新編號。
     - 公式裡可省略的成分不寫（มีอะไร + ก็ + 動詞，不寫「（主詞）」）。
     - 也要列：順序詞的用法並比較近義說法（名詞 + ต่อไป，cmp 說明 ครั้งหน้า／อาทิตย์หน้า 的 หน้า）、程度補語（動詞／形容詞 + หมด「全都…；…死了」）。可以比 3–4 個多，老師要的都列。
     - `cmp` 寫短，或留空；不寫語氣、用法的長篇說明（老師刪掉了「語氣輕鬆、有點不太確定地做決定」「帶出好處或目的」這類）。
   - 切句：同一個人連著說、意思相連的短句合成一句（例：ไม่ได้จริง ๆ หรอ＋ใจดำ；จองเลยที่＋結尾 Logo 的品牌名）。
     - 清單類影片：連著唸的品項照字幕段落分句（เสื้อกันหนาว หมวกไหมพรม ผ้าพันคอ／กางเกงวอร์ม ถุงเท้า），不要一個品項一句，也不要全部塞一句。
     - 劇情廣告的長旁白照畫面字幕段落切，一段一句，不要把好幾段合成一長句（ในทุกๆ โรงเรียน／ขอเพียงมีครูสักคนหนึ่ง ที่มองเห็นได้ว่า／การวัดผล…อย่างเดียว／ไม่สามารถบอกได้ว่า… 是四句；ครูอาจจะเงอะงะนิดนึงนะ／แต่ว่าจริงๆ แล้วครูมีตัวช่วย 是兩句）。
     - 片尾只有品牌 Logo、口號的字卡不收（7-Eleven 的 เชิดชูครูผู้สร้างการเปลี่ยนแปลง 老師拿掉了）。
     - 劇集片段（已燒字幕）照字幕段落切，同一人連著說的也分開（《鎮靈》：มีอะไรพ่อก็พูดออกมา／ไม่ต้องมาอ้ำๆ อึ้งๆ、อะไร จ่า／ตกใจหมด 老師都拆成兩句）。
     - 問句和回答分開：อุ๊ย ฮู้ดดี้กับเสื้อกันหนาว…ป่ะ／คนละอันค่ะ／ฮู้ดดี้ค่ะ 是三句。
   - `quiz`（閱讀練習）：3 題，形狀同歌曲（`q`、`qZh`、`options`、`answer`、`explain`），問影片內容；清單類影片放一題「哪一樣沒有提到」。
   - `order`：老師指定列表順序時填（1 最前面）；沒填的照 `createdAt` 排在後面。
   - `topic`、`level`、`titleZh` 填好；`tips` 可省略。
   - `culture`（文化補充，放在小測驗後面；老師要求才加）：`title`、`intro`，加上 `pyramid`（金字塔：左邊職務、中間官階＋泰文縮寫→稱呼、右邊 `duty` 職務內容；`also` 讓同一個官階兩色各半，`entry` 標畢業起點）或 `table`（小表）或 `items`（詞條）。投影片上金字塔一頁、小表另一頁。範例：《鎮靈》的泰國警察稱呼。
     - 劇裡的稱呼要講清楚是職務還是官階：上面幾層用職務叫（สารวัตร、ผู้กำกับ），下面用官階叫（ผู้กอง、หมวด、จ่า）；ผู้กอง／หมวด／หมู่ 來自軍隊的連／排／班。
     - 中文字幕的「警長」是港片用法＝基層士官（จ่า），不是美國的 Sheriff。
   - `note` 是給老師看的製作說明（字幕怎麼校對、哪些音標自己補的），頁面只在 `?edit=1` 顯示，學生看不到；內容尚未製作的空殼才會對學生顯示。
4. **完成標準**：每一句都有 `zh`，每個字都有 `rom` 和 `zh`。`patterns` 列的 id 都有定義，`p` 也都對得上。

## 驗證並交棒

1. 跑 `npm run build`，要通過。
2. 叫使用者開 `npm run dev`，到這首歌或這支影片的頁面校對：
   - 歌曲：老師模式可以隱藏句子、合併句子，按「編輯斷詞／音標／中文」修改，存檔寫回 JSON。
   - 影片：網址加 `?edit=1` 進校時模式，用「打起點」修正每句起點，再按「儲存回 JSON」。
   - 兩邊都可以看「🖥 投影片模式」和「🖨 列印講義」有沒有跑版。
3. 回報：做了幾句、哪些句子標了 `guess`、`note` 記了哪些字幕問題、哪些音標是網站查不到自己補的。
4. **老師校對期間只就地改 JSON**：先讀現在的檔案，只改老師要求的地方；不要用草稿腳本整份重新產生，否則會蓋掉老師「儲存回 JSON」存的起點（7-Eleven 那支就被蓋掉一次，老師得重打）。拆句時只有新句用估計起點，回報時列出來請老師重打。
5. **停在這裡**，等老師校對完。使用者說要 commit 才 commit；commit 只放這支影片或歌曲的 JSON（和圖片），加上這次為了老師要求改的程式和這份 skill。
