# 泰時刻約課系統｜第一版：AmazingTalker 信件同步

讀取 Gmail 裡 AmazingTalker 的通知信（課時請求、學生取消），寫進 Google 試算表與專用行事曆。
你在 AmazingTalker 確認或拒絕後，回試算表把「狀態」改掉，行事曆會跟著更新。

需求文件：Claude 專案「泰時刻約課系統｜需求文件」。

## 它會做什麼

| 收到的信 | 試算表 | 行事曆（專用行事曆「泰時刻課表」） |
|---|---|---|
| 課時請求 | 新增一列，狀態「待確認」 | 灰色暫定事件，標題有【待確認】 |
| 你把狀態改成「已確認」 | 狀態更新 | 變成綠色正式課程 |
| 你把狀態改成「已拒絕」 | 狀態更新 | 事件刪除 |
| 請求超過 24 小時沒處理 | 狀態變「已過期」 | 事件刪除 |
| 學生取消信 | 狀態「已取消」並記下原因 | 事件刪除 |
| 看不懂或找不到對應的信 | 狀態「請人工確認」 | 不動 |

- 25 分鐘的課佔行事曆 30 分鐘，50 分鐘的課佔 60 分鐘。長度不是 25 或 50 時不會自己猜，標「請人工確認」。
- 請求過期前 4 小時，會寄一封提醒信給你，列出還沒處理的請求。
- 有需要你看一下的事（重疊、看不懂的信、錯誤）會寄信給你，不會默默漏掉。
- 平台**不會**在你確認後寄信給你，所以「已確認／已拒絕」一定要你回試算表標記。
- 程式**不能**幫你在 AmazingTalker 上關閉時段，私下學生約定的時間仍要你手動關。

## 設定步驟（約 15 分鐘，只做一次）

請全程使用**收到 AmazingTalker 通知信的那個 Google 帳號**。

### 1. 在 Gmail 建立篩選與標籤

1. Gmail 右上角齒輪 → 查看所有設定 → 篩選器和已封鎖的地址 → 建立新的篩選器。
2. 「寄件者」填 `amazingtalker@mailer.amazingtalker.com` → 建立篩選器。
3. 勾選「套用標籤」→ 新增標籤，名稱輸入 `AmazingTalker`。
4. 勾選「也要將篩選器套用到相符的對話」→ 建立篩選器。

不要勾選「略過收件匣」，信還是要留在收件匣。

### 2. 建立試算表

1. 打開 https://sheets.new ，檔名取「泰時刻約課」。
2. 檔案 → 設定 → 時區選「(GMT+08:00) 台北」。

### 3. 貼上程式碼

1. 在試算表選 擴充功能 → Apps Script。
2. 左邊「專案設定」（齒輪）→ 勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」。
3. 回到「編輯器」。把這個資料夾裡的檔案一一貼進去：
   - `appsscript.json`：貼到已有的 appsscript.json，整份取代。
   - `Config.gs`、`Parser.gs`、`Logic.gs`、`Sheets.gs`、`CalendarOps.gs`、`Sync.gs`、`Menu.gs`：
     原本的 `Code.gs` 內容刪掉後貼入 `Config.gs`；其餘用「檔案 +」→ 指令碼，名稱不用加 `.gs`，貼上內容。
4. 按儲存。

### 4. 授權並初始化

1. 重新整理試算表分頁，上方會出現「泰時刻」選單（要等幾秒）。
2. 選 泰時刻 → 初始化分頁。第一次會跳出授權視窗：
   - 這是你自己寫的程式，Google 會顯示「尚未驗證」。選「進階」→「前往（不安全）」→ 允許。
   - 它會要求讀取 Gmail、建立行事曆事件、編輯這份試算表、寄信給你自己。
   - **程式只讀有 `AmazingTalker` 標籤的信，不會碰其他信。** 但 Google 的授權畫面對 Gmail 只有「完整存取」這一級，所以會寫得很廣。
3. 授權後再選一次 泰時刻 → 初始化分頁。

### 5. 填學生表

「學生」分頁填：`姓名`、`平台顯示名稱`（信裡出現的名字，例如 Amy）、`Email`。
沒填也能跑，只是「預約」分頁的學生欄會直接用平台顯示名稱，並在備註提醒你補上。

### 6. 第一次同步

1. 泰時刻 → 立即同步 AmazingTalker 信件。
2. 檢查三個地方：「預約」分頁有沒有新增、Google 行事曆多了「泰時刻課表」、「信件紀錄」分頁每封信的處理結果。
3. 結果正確後，選 泰時刻 → 安裝自動同步。之後每 10 分鐘自動跑，修改「狀態」欄時行事曆立即更新。

### 日常使用

1. AmazingTalker 寄來課時請求 → 約 10 分鐘內出現在試算表。
2. 到 AmazingTalker 確認或拒絕。
3. 回試算表，把那一列的「狀態」用下拉選單改成「已確認」或「已拒絕」。

## 第一次上線請特別檢查

程式是用信件的文字格式寫的，但我只看過兩封樣本（請求、取消），而且是從 PDF 看到的。
第一次同步後請對照真實的信，看「開始」「實際結束」「課長」有沒有對。
如果有信被標「無法解析」或數字不對，請把那封信的內容給我，我再調整。

## 本機測試（不需要 Google 帳號）

```bash
node --test apps-script/test/*.test.js
```

- `parser.test.js`、`logic.test.js`：解析與規則。
- `sync.smoke.test.js`：用假的 Gmail、試算表、行事曆跑完整流程，抓接線錯誤。
- `fixtures/`：樣本信。依真實信件的格式改寫，學生名是代稱，**不要放真實學生姓名或 Email**。

## 檔案說明

| 檔案 | 作用 |
|---|---|
| `Config.gs` | 標籤名稱、行事曆名稱、提醒時間等設定 |
| `Parser.gs` | 解析信件（純函式，可在 Node 測試） |
| `Logic.gs` | 課長、30 分鐘取整、狀態與重疊判斷（純函式） |
| `Sheets.gs` | 試算表讀寫 |
| `CalendarOps.gs` | 行事曆事件 |
| `Sync.gs` | 主流程：讀信、過期、對齊行事曆、提醒 |
| `Menu.gs` | 「泰時刻」選單與觸發器安裝 |

## 已知限制

- 信件格式改版會讓解析失效；失效時會寄信通知你。
- 信件約有幾分鐘延遲；AmazingTalker 與私下學生同時搶同一格仍可能撞，建議把每週時段分成兩區。
- 取消信只有學生名與開始時間，用它們對應原預約；系統上線前就有的課，取消時會標「請人工確認」。
- 學生同名時無法區分。
- 還沒做：私下學生預約頁、Zoom、課前提醒（第二版）。
