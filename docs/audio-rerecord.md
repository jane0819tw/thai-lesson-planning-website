## 音檔來源紀錄

`public/audio/sources.json` 記錄每段音檔來自哪裡（`edge-tts` 或 `gtts`），日後整批換成官方服務或真人錄音時用。

- **gTTS**：母音卡相關的音。(1) 母音鈕「直接念母音本身」：單一符號念符號（ะ า ิ ี ึ ุ ู 等），多符號補 อ 念（เอะ、เออ、แอะ…），規則同 `src/strokes.ts` 的 `vowelSpeech`；(2) 母音卡短音、長音例字（กะ กา กิ กี เกะ เก…）。由 `gen-audio.py` 依課程資料自動推出。edge-tts 唸這類音會跑掉。
- **edge-tts**：其他所有詞（含帶子音的音節，如 กะ กา กิ）。
- 母音鈕的發音文字由 `vowelSpeech`（`src/strokes.ts`）決定，`gen-audio.py` 內的 `vowel_speech` 必須與它保持一致，才會對到音檔。
- 試過但放棄的做法：「สระ ＋ 名稱」（gTTS 會忽略空格、把 สระ 念成 หระ，結果不穩定）、改拼 สะหระ（仍不理想）。

## 目前的暫時做法（edge-tts）

- 單獨「子音＋อ」音節（如 กอ）：用「กอ กอ กอ」連唸，切出第一個（`BARE_RATE = -45%`），約 0.36 秒，偏短。
- 子音名稱：合成時保留中間空格（`กอ ไก่`），manifest 的 key 仍是去空格版（`กอไก่`）。
- 這些都只是繞過 edge-tts 的限制，無法真正指定聲調。
- 單音節長度（約 0.36 秒）已決定維持現狀，不再調整，因為這批會重錄。
- L2 的 เกะ、เจ、ก้ะ、ปู、ดูดีดี 尚未生成音檔（目前只生成到 L1），L2 生成前要先決定這些是否直接等重錄版本。

## 拿到 Azure 金鑰後要做的事

1. 在本機 `.env.local` 放 `AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`（`.gitignore` 已排除 `*.local`，金鑰不要進版本控制、不要貼進對話）。
2. 把 `scripts/gen-audio.py` 的合成改成呼叫 Azure Speech，使用 SSML：
   - `<phoneme alphabet="ipa" ph="...">` 直接指定第一聲（平調）發音。
   - `<prosody pitch="..." contour="...">` 調整音高曲線，避免尾音下滑成低調。
   - `<prosody rate="...">` 控制長度，解決太短促的問題。
3. 先只重生上表的詞，聽過滿意再套用到其他課。
4. 重生方式：刪掉該詞在 `public/audio/manifest.json` 的條目與對應 mp3，再執行 `python3 scripts/gen-audio.py lesson-01 ...`。

## 備案：真人錄音

若 SSML 仍調不準，這幾個音改用真人錄音（mp3），以檔名 hash 覆蓋或在 manifest 指向新檔即可，不需改前端。

## 驗收方式

開 `/#/reading/lesson/lesson-01`，聲調表按「▶ 一到五聲」，確認第一聲是平調、不會像第二聲，且長度與其他四聲相近。

## 語音來源的使用條款與風險（公開或商用前必讀）

目前專案裡預錄音檔的來源都是**非官方管道**，自用教學、靜態檔案風險不大，但網站若要公開給不特定對象、收費或商用，要先處理：

| 來源 | 官方？ | 風險 | 公開／商用前建議 |
|---|---|---|---|
| edge-tts（Premwadee / Niwat） | 否，借用 Edge 瀏覽器朗讀功能的介面 | 微軟隨時可能改介面或限制，使用條款不保證可用於商用 | 改用官方 Azure Speech（Free F0 每月 50 萬字，需訂用帳戶） |
| gTTS（Google 翻譯語音） | 否，呼叫 Google 翻譯網頁用的介面 | 可能被限流或停用；使用條款是灰色地帶，沒有授權商用 | 改用官方 Google Cloud TTS（需 Google Cloud 帳戶與信用卡） |
| Azure Speech／Google Cloud TTS | 是 | 要確認各自條款對「預錄音檔再散布」的規定，用量超出免費額度會計費 | 公開前再讀一次當時的條款與價格 |
| 真人錄音 | — | 自己錄的沒有授權問題；請人錄要書面約定授權範圍 | 重點教材（聲調、母音）優先採用 |

要注意的事：

1. **只當靜態檔案用。** 一律預先生成 mp3 放進 `public/audio/`，不要讓網站在使用者端即時呼叫這些非官方介面。
2. **不要把非官方語音當成產品賣點。** 例如不要宣稱「AI 語音」或販售音檔本身。
3. **要公開或商用前**：把用到的音檔改由官方服務（Azure Speech 或 Google Cloud TTS）重新生成，或改成真人錄音，再覆蓋 `public/audio/`。重生流程見上方「拿到 Azure 金鑰後要做的事」，前端不需要修改。
4. **記錄每批音檔的來源。** 混用多個來源時（例如母音用 gTTS、其他用 edge-tts），在本文件或 manifest 旁註明，才能日後整批替換。
5. 這裡的描述是開發時的理解，不是法律意見；各服務條款會變，實際公開前請以官方最新條款為準。
